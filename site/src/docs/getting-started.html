From download to a first contained agent task in a few minutes. You bring the model; Ferrite brings the browser and the defense.

1. Install

Grab the build for your system from the download section. Builds are unsigned prototypes, so each platform asks you to confirm once.

PlatformFileFirst launch
macOS (Apple silicon)ferrite-<commit>-macos-arm64.zipUnzip, drag Ferrite.app to Applications, then right-click and choose Open.
Windows (x64)ferrite-<commit>-windows-x64.zipUnzip and run ferrite.exe. If SmartScreen appears, choose Run anyway.
Linux (x64)ferrite-<commit>-linux-x64.tar.gzExtract, then ./ferrite, or ./install.sh to add a launcher entry. Needs a graphical session.

Prefer to build it yourself? See Build it from source.

2. Connect a model

The agent needs a language model. Until you connect one, the agent panel shows No AI model connected with an Open settings button, and the browser itself works as a normal browser.

  1. Click the gear in the toolbar (or Open settings in the agent panel).
  2. Under AI model, choose a provider: Ollama Cloud, Ollama (this computer) or Google Gemini.
  3. For a hosted provider, paste your API key. Get one at ollama.com/settings/keys or aistudio.google.com/apikey. For local Ollama there is no key; check the server address and that Ollama is running.
  4. Press Load models. Ferrite asks the provider what your key can use, which also confirms the key works. If it fails, the message says why (rejected key, unreachable server, timeout).
  5. Choose a Fast model. By default the same model also serves as the Agent model; untick Use the same model to choose a stronger one for driving the browser.
  6. Press Save and use. The status card turns to Connected and the next agent task uses it. No restart.

What the two models do

The fast model runs once per task to predict which capabilities the task might need, beyond what a deterministic rule layer already pinned down. The agent model reads pages and chooses each step. A small model is fine for the first; a stronger one helps with the second.

Details, including where keys and settings are stored and how environment variables interact, are in Models and settings.

3. Run a task

  1. Open the Agent panel (toolbar, or Ctrl+Shift+O for a new chat).
  2. Describe what you want in plain words, for example “Summarize the top stories on Hacker News”.
  3. Watch the activity feed: each step shows what the agent did and what came back.

Ferrite derives the task's expected fingerprint from your words only. Earlier agent answers and page text never feed it, so a poisoned page cannot widen what it is allowed to do.

4. When the consent prompt appears

If the agent attempts something outside what your request implied, a panel titled Unexpected activity detected lists each item in plain language, for example:

  • Used tool: js.execute. Arbitrary JavaScript is always reviewed; nothing in your request could have authorized it.
  • Contacted https://attacker.example. This origin is not authorized. Your request authorized https://news.ycombinator.com.

Approve or reject each item, then Proceed with approved or Cancel. Rejected items are blocked for the run. If you are unsure, reject: a rejected legitimate action costs you a retry, an approved malicious one can cost much more. The Show dry-run evidence toggle reveals what the rehearsal recorded.

The Audit panel (F12) shows the hash-chained log and the model-activity trace.

Where your data lives

Everything is under one data directory: $FERRITE_HOME if set, otherwise ~/.local/share/ferrite on every platform. It holds the browser profile (cookies and storage persist across restarts), saved chats, bookmarks, settings.json and the activity log. API keys are not there; they go to your operating system's credential store.

Troubleshooting

No AI model connected
Open Settings and finish steps 2 to 6 above. The agent fails closed without a model: it will not act without one.
“The provider rejected this key”
The key is wrong, revoked, or for another provider. Re-paste it; keys are shown masked.
“Could not reach Ollama at …”
Start Ollama on this computer, then press Load models again. A local server must be localhost or 127.0.0.1.
The key vanished after a reboot (Linux)
On Linux the key is held in the kernel keyring, which a restart clears. Export OLLAMA_API_KEY (or FERRITE_GEMINI_API_KEY) in your shell profile for a permanent key.
My saved choice is ignored
An exported FERRITE_MODEL_* variable overrides the file. Settings names the variables that are overriding it.
