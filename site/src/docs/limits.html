A security project that hides its weaknesses cannot be evaluated. This page gathers every known limit in one place: what the defense cannot stop, what the evaluation cannot show, and what the product cannot do yet. Where a limit is pinned by a test, the test stays in the repository, so the limit cannot quietly disappear.

Ferrite is a research prototype

Do not use it to protect anything you cannot afford to lose. The numbers in the documentation describe an architecture under a particular experiment, not a guarantee.

Limits of the defense

The residual: attacks inside the prediction

The architecture contains every attack that needs an action outside what the task implied, and nothing else. An attack that uses the same capability at the task's own site, or that is data-only (for example, tampering with the content a legitimate action returns), is indistinguishable from the task. In the evaluation this is 122 of 809 attacks (15.1%) with the sanitizer off. It is reported as a floor and kept in every denominator.

Open-ended scopes

Under a task_open scope every origin is admitted, so nothing distinguishes the attacker's destination. An open-ended prompt that matches no rule produces an empty fingerprint, which sends everything to consent. That is safe but noisy; a follow-up like “do the same for the second one” predicts a looser fingerprint because the dry run sees no page content, and may raise more prompts. The fail-safe direction is accepted.

The sanitizer

It is pattern matching over de-obfuscated views. It misses, by construction and pinned by tests: paraphrase, languages outside its list, syllable hyphenation, spelled-out markup or URLs, reversed non-Latin text, and payloads split across separate elements. It also has known false positives: pages that discuss attacks (“attackers exfiltrate data”, “never ignore the previous warnings”) and any mention of “system prompt”. The architecture does not depend on it.

The runtime guard

  • A click by CSS selector, a form action (submit, Enter in a field) and a server-side redirect cannot be resolved to a destination before they run. The tab's new origin is checked on the next action, after the request has been made.
  • A trailing-dot host (example.com.) fails closed.
  • Within-fingerprint abuse is indistinguishable from the task, by construction.

The human

The consent gate is a person. A user who approves everything defeats it: in the original run, approving every flagged action left 45.5% of attacks succeeding, against 0% when every flagged action is rejected. Real behavior is somewhere in between, and no human-factors study has measured where.

The model

Ferrite bounds what a compromised agent can do. It does not make a model less gullible. A model that is fooled will still try the action; the defense is that the attempt is contained, not that it is never made.

Limits of the evaluation

  • The agent is scripted. It re-enacts each case's authored deviation from ground truth, so the results say nothing about how often a real model takes the bait.
  • The fingerprint is rules-only by default. The 0% false-gate rate is for a well-behaved scripted agent under that prediction. A real agent's rate depends on what it does and on the model prediction layer, which the default run does not exercise.
  • Self-authored and generated. The corpus was written by the defense's author and expanded from shared templates, then tuned against. The intervals treat matrix-correlated cases as independent, so they understate the uncertainty.
  • No independent slice to speak of. Only three external (AgentDojo) cases exist, which supports no claim. There is no second author, so Cohen's κ for annotation agreement is not computable and has not been faked.
  • ADR = 100% is by construction. It measures the comparator against a scripted agent that issues exactly the declared deviation.
  • Missing quantities. Task-completion parity for benign tasks (no benign baseline under Off) and extra token cost (no token usage in the execution record) are not computed, for stated reasons.
  • A live-provider run is not reproducible byte for byte, so it is reported separately.

Limits of the product

  • Unsigned builds. Each platform asks you to confirm the first launch.
  • Web compatibility is Servo's. Ferrite renders with the Servo engine. Some web platform features are still absent there (for example requestIdleCallback, adoptedStyleSheets, FontFace, OffscreenCanvas and the Navigation API), so some sites will not work, and Google sign-in may refuse an embedded engine.
  • Linux keys do not persist across a restart with the kernel-keyring backend this build uses; see Models and settings.
  • Cookies are written on clean shutdown. Closing the window saves the profile; a crash, a kill or macOS Cmd+Q that bypasses the window close loses that run's new cookies.
  • The packaged builds are new. The three-platform packaging and release pipeline was written recently; check the release page for what has actually been published.

What is explicitly not claimed

  • That Ferrite makes AI browsing safe, or safe in production.
  • That any model is robust to prompt injection because it sits behind Ferrite.
  • That the evaluation generalizes to attacks, tasks or sites outside the corpus.
  • That users will reject unexpected actions; the headline numbers assume they do.
  • That the defense survives an attacker who has read it. The corpus was tuned against, and no held-out, adversarial, independently authored evaluation has been run.
  • That the sanitizer detects injected text in general. It detects the patterns it has.

What would make the claims stronger

  • An independently authored, held-out corpus, run once, with a defense brief withheld from the authors.
  • A run with real models as the agent, reporting how often they take the bait and what the defense contains.
  • A human-factors study of how people actually answer consent prompts.
  • The model prediction layer measured on its own, with the sanitizer and rules off.

If you can do any of these, or find an attack that gets through, open an issue. A bypass is a result, and the corpus is where it belongs.
