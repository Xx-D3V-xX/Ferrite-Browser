Agentic browser · built on Servo

Let the agent browse.
Contain it when a page fights back.

Ferrite is a browser for AI agents that defends against indirect prompt injection by architecture. It does not try to spot every malicious sentence on the web. It predicts what your task should need, and stops the agent the moment it reaches for anything else.

The problem

An agent that reads the web can be told what to do by the web.

Anything an agent reads, whether a page, a tool result or a search snippet, is text it might obey. An attacker only needs to put instructions where the agent will look.

{{icon:eye}}

Hidden in plain sight

A hidden <div>, an HTML comment, an image alt attribute, a field in a tool's JSON response. Users never see it. Agents do.

{{icon:list}}

Phrasing has no end

Paraphrase, other languages, encodings, look-alike letters. Pattern matching on text is an arms race the defender has to win every time.

{{icon:layers}}

So watch the behavior

Whatever the injected text says, a successful attack ends the same way: the agent does something the task never needed. That is what Ferrite checks.

The defense

Predict. Dry-run. Compare. Ask.

Four stages decide what an agent may do, and each one is built so that a hostile page cannot talk its way past it.

Predict

From your request alone, before any page is read, Ferrite works out which capabilities and which sites the task legitimately needs. A deterministic rule layer, plus an optional model for what it might need.

fingerprint = must_use ∪ may_use

Dry-run

The agent's plan is rehearsed against synthetic, plausible data with no real network reachable, so a deviation shows up with nothing real at stake.

synthetic twin · no network

Compare

What the agent attempted is compared with what was predicted. Anything outside it, a different site, a download, a script, is a deviation. js.execute always is.

actual ⊆ predicted ?

Consent

Each deviation is shown to you item by item, in a trusted panel decoupled from page content. Approve, reject, or cancel the whole task.

nothing real runs first
{{icon:block}}

A guard on the real run

The dry run cannot see a page that only exists in the real run, so every real action is checked again before it executes. A blocked action tells the agent a fixed sentence, never anything the page wrote.

{{icon:shield}}

A sanitizer, as a first layer

Instruction-like text is detected across de-obfuscated views (look-alikes, encodings, eight languages) and cut out. It lowers risk, but the guarantee never depends on it.

{{icon:chain}}

A log you can verify

Security-relevant events go into a SHA-256 hash-chained audit log, so a containment decision can be checked afterward, not just asserted.

What you see

A consent prompt the page cannot forge.

When the agent steps outside the prediction, the panel lists every unexpected action in plain language, with the origin your request actually authorized beside it. You decide per item.

  • {{icon:check}}Unforgeable by content. The prompt is drawn by the browser, not the page, and only your own words feed the prediction.
  • {{icon:check}}Fail to empty. A model error, a timeout or a missing key empties the prediction, so more actions ask you, never fewer.
  • {{icon:check}}No script escape hatch. Running arbitrary JavaScript can synthesize any other action, so it is never part of any prediction at any scope.
  • {{icon:check}}It asks again during the real run. The dry run cannot see a page that only exists in the real run, so an action outside the prediction pauses the agent with Don’t allow, Allow once or Allow for task.

The browser

A browser around the defense, with tools for when a page misbehaves.

Ferrite renders with the Servo engine and wraps it in an ordinary browser: tabs, an address bar that searches Google, find, zoom, bookmarks, and an agent panel on the side. It is a young engine, so some sites will look wrong. When one does, you can see why.

{{icon:terminal}}

DevTools

Console, Network and Engine tabs in a bottom panel. Cmd+Opt+I on macOS, Ctrl+Shift+I elsewhere, or Cmd/Ctrl+J. F12 opens the audit log instead.

{{icon:layers}}

Page controls

Dropdowns, alert/confirm/prompt, colour and file pickers and right-click menus are drawn by Ferrite as overlays. The page is blocked until you answer, and its text is shown as plain text.

{{icon:list}}

Logs you can send

Launched without a terminal, Ferrite writes a log file, and a crash leaves the page frozen under a banner with Reload. A script gathers the log, crash reports and system details into one zip.

Pages are drawn on the CPU, except on macOS, where Ferrite tries the GPU first and falls back to the CPU if a startup self-test fails (FERRITE_RENDERER=gpu|cpu|auto overrides the choice). The GPU path has never run on a real GPU or on a Mac, and no speed-up has been measured.

DevTools

See what the page said, and what it asked for.

The Console keeps every message the page printed, at every level, per tab, with a filter, level chips and a prompt that runs JavaScript in the page. The Network tab lists each request as it starts. The Engine tab lists panics and pages whose script thread died.

  • {{icon:check}}Copy, save or open the folder. A tab can be copied as text or saved as a log file in the app's log folder.
  • {{icon:check}}Resizable panels. Drag the edge of the agent, library, settings, DevTools or audit panel; double-click it to reset. Sizes are remembered.
  • {{icon:block}}The Network tab is incomplete. It shows method, type and URL, but not status, size or timing: the engine does not report them yet.

A real model in the loop

The numbers above come from a scripted agent. A separate runner, live_eval, puts a real model in the agent's seat and in the predictor's: Gemini or Ollama, in batches under a hard call cap, with rate-limit backoff and resume. --plan prices a selection first and calls nothing. No real model has been run through it yet, so there are no results to show. How it works

{{icon:scale}}

All of AgentDojo, imported

1,046 cases (949 attacks and 97 benign twins) from AgentDojo v1.2.2 at a pinned commit, parsed and never executed, with labels from the specification rather than from Ferrite's own output. They feed the live runner and are not part of the 938-case headline corpus, which still holds only three external cases. Details and caveats

Read this before you quote a number

  • The agent is scripted, not a real model. The corpus runner makes the agent carry out each case's authored deviation, so the numbers say nothing about whether a real model would take the bait. That is the base model's robustness, and Ferrite does not claim it.
  • The headline assumes you reject what is flagged. The reported rate is the upper bound on human vigilance. In the original 29-case run, a user who approves everything left 45.5% of attacks succeeding.
  • The corpus is self-authored and generated from templates. The intervals treat cases as independent draws, which a matrix is not, so they understate the uncertainty. No second author exists yet for a κ agreement score.
  • The residual is real and by construction. An attack that uses the same capability at the task's own site is indistinguishable from the task.

Your model, your key

Connect an agent in Settings. No terminal needed.

Pick a provider, paste a key, load the models your account can use, choose one, and save. It takes effect on the agent's next task.

  • {{icon:check}}Ollama Cloud, local Ollama or Google Gemini. With local Ollama, no page text leaves your computer.
  • {{icon:key}}Keys live in your OS credential store. macOS Keychain or Windows Credential Manager; never in a file, never in a log. On Linux it is the kernel keyring, which a restart clears, so export the key as an environment variable if you want it to stay.
  • {{icon:check}}Models come from your account. “Load models” asks the provider what your key can use, which also checks that the key works.
  • {{icon:check}}One model or two. A small fast model predicts what the task needs; a stronger one drives the browser. Use one for both if you prefer.

The agent sends page content to whichever model you choose, because it needs it to act. Environment variables still override the saved choice, for CI and power users. Only Ollama and Gemini are supported: there is no OpenAI-compatible or Anthropic backend yet.

Check which commit a build comes from

The release page names the commit. The build published on 2026-10-02 (commit f4ed744) predates the DevTools panel, resizable panels, page-control overlays, the crash banner, the GPU renderer, the display-scale fix, Google address-bar search and the log-collection script shown on this site. They are in the source and arrive in the next build that CI publishes. Until then, build from source to try them.

Or build it from source

You need a recent Rust toolchain (the repository pins stable) and a C toolchain with cmake and pkg-config. The first build compiles the Servo engine: plan on 20 to 60 minutes and 10 GB or more.

$ git clone https://github.com/rayanjainn/Ferrite-Browser
$ cd Ferrite-Browser
$ cargo run --release -p ferrite-shell --features ferrite-servo/servo

With just installed, just setup-servo then just run-fast --no-model-check does the same through the helper scripts; connect a model from Settings once it opens. Run it from source lists every recipe and what it needs.

Without the Servo feature the whole defense, the evaluation harness and the test suite still build and run (just test, or cargo test --workspace), with no network and no API key. That build opens the interface but cannot render web pages.
