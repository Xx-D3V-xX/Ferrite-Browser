## How to resume

1. `git fetch && git checkout feat/perf-search-devtools-eval`.
2. `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`
   and `cargo test --workspace` (or `cargo test -p <crate>` for each crate when disk
   is short). The last run recorded in `docs/PROGRESS.md` had clippy and fmt clean and
   `cargo test -p ferrite-ui` at 501 passing; re-run before relying on it.
3. To look at a page without the app: build and run `page_shot`, about 15 minutes cold
   (`just page-shot https://example.com 8000 /tmp/x.png`, or
   `cargo run -p ferrite-servo --features servo --example page_shot -- <url> [wait_ms]
   [out.png] [width] [height] [scale]`). It needs the real Servo build and, for a real
   site, a network.
4. Merge to `main` or open a PR when the owner says so. Then run **CI** from the
   Actions tab (manual; a green run publishes the `latest` release automatically) and
   the **Site** workflow if the project site changed.
5. Ask the owner for: `ferrite.log` (or `just collect-logs` output) from the new macOS
   build, the `[ferrite-render]` line, which pages still fail, and the live-eval
   results once they have run it (`docs/COMMANDS.md` §6).
