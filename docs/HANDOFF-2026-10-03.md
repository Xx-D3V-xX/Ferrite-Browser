## How to resume

1. Run `git fetch && git checkout feat/perf-search-devtools-eval`.
2. Run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D
   warnings` and `cargo test --workspace`. If disk is short, run `cargo test -p
   <crate>` for each crate. The last run recorded in `docs/PROGRESS.md` had clippy
   and fmt clean. In it, `cargo test -p ferrite-ui` had 501 tests passing. Run them
   again before you rely on that.
3. To look at a page without the app, build and run `page_shot`. A cold build takes
   about 15 minutes. Use `just page-shot https://example.com 8000 /tmp/x.png`. Or use
   `cargo run -p ferrite-servo --features servo --example page_shot -- <url> [wait_ms]
   [out.png] [width] [height] [scale]`. It needs the real Servo build. For a real
   site it also needs a network.
4. Merge to `main`, or open a PR (pull request), when the owner says so. Then run
   **CI** from the Actions tab. It is manual. A green run publishes the `latest`
   release by itself. Also run the **Site** workflow if the project site changed.
5. Ask the owner for these things:
   - `ferrite.log` (or the output of `just collect-logs`) from the new macOS build;
   - the `[ferrite-render]` and `[ferrite-webgl]` lines;
   - which pages still fail;
   - anything more from the live evaluation. The results of the real run are already
     in `docs/results/live-eval-ollama-gemma4-31b.md`. The commands are in
     `docs/COMMANDS.md` §6.
