**Landed (`61ed9f0`+`3981f8a`):** hand-authored SVG icon set, `icon()`
rendering helper, chrome visual polish (nav/toggle buttons, tab bar
close-on-hover, consent-panel icons), one tick-based transition (consent
panel entrance). See `docs/PROGRESS.md`'s 2026-09-23 C1 entry for full
detail — this file is only "what C2 reuses and does next."

## Exact next action for C2 (agent panel redesign)

Rebuild `view_agent_sidebar` (`crates/ferrite-ui/src/lib.rs`) into a live,
step-by-step action view: visible plan/reasoning, a scrollable action
history with per-step results (not just the flat `agent_tool_log: Vec
<String>` label list it renders today) — built **on this charter's tokens
and helpers, not a second visual language**:

- **Icons:** `icons.rs`'s `Icon` enum + `icon(kind, size, color) ->
  Element`. `Agent`/`Play`/`Stop`/`Approve`/`Reject`/`Warning`/`Origin`
  already wired in; add new `.svg`s under `assets/icons/` in the same
  24x24 stroke style for anything new (e.g. a per-step status glyph).
  Every icon needs a real, non-test call site the moment it's added —
  `Bookmark`/`Settings` were drawn but deliberately left OUT of the enum:
  an unconstructed variant fails `clippy --all-targets -D warnings` even
  with a test constructing it (dead-code lint runs the lib target
  separately from tests) — see `icons.rs`'s own comment. Add variant +
  call site together, never just the variant.
- **Colors:** existing `C_*` tokens plus this charter's `ICON_SIZE`/
  `ICON_SIZE_SM`. Extend, don't replace, absent a real reason not to.
- **Style helpers:** `nav_btn_style`/`panel_btn_active`/`panel_btn_inactive`/
  `accent_btn_style`/`close_btn_style`/`separator_style` — reuse for any
  new button/toggle; extend the shared `button::Status` hover/press
  pattern rather than reinventing one per widget.
- **Animation:** `ease_out_cubic(t)` (pure, tested) plus the
  `ConsentPanelTick`/`consent_panel_anim` pair's shape (a `Subscription`
  gated on "is this actually animating," advancing a linear `f32` in
  `update()`, eased in `view()`) is the reference for a per-step reveal
  animation if wanted. Give it its own state field/gate — don't reuse
  `consent_panel_anim` itself for an unrelated animation.
