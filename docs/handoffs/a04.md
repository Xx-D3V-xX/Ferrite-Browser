**Landed:** `crates/ferrite-ipi/src/fingerprint/{mod,rules,engine}.rs`.
`rules::rule_based_must_use` — deterministic keyword layer, retyped from
`tool_decision::rule_based_must_use` against `ferrite_core::Capability`
(that old module is untouched, kept as reference per `docs/AUDIT.md`).
`engine::generate_fingerprint` — calls `&dyn ferrite_model::ModelProvider`
(never a concrete backend) to predict `may_use`, filtered against
`Capability::ALL` by exact string match. `Fingerprint::new` is private and
the only non-empty constructor; it subtracts `must_use` from the candidate
`may_use`, so disjointness is a construction invariant, not a convention.
`predict_may_use` is two `let-else` guards, so every provider failure
(transport, timeout, 429, 5xx, oversized/empty/malformed body, budget
exhaustion) returns before the insertion step is reachable — fail-to-empty
by control flow. `js.execute` is structurally absent because `Capability`
has no `Execute`-class variant at all; a `compile_fail` doctest on
`Capability::JsExecute` plus a unit test under the worst-case input (every
capability claimed plausible) pin this down at the module boundary.

**One real gap found and fixed before landing:** the "skip the model call
when nothing is left to predict" branch was unreachable through the public
`generate_fingerprint` alone — `rule_based_must_use` has no clipboard
keywords, so `must_use` can never cover all seven capabilities. Factored a
private `generate_from_must_use(provider, model_tag, prompt, must_use)` so
the test can drive that branch with a synthetic `must_use` directly, rather
than leaving an actually-untriggerable branch untested.
