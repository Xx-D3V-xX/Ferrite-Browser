**Landed (`crates/ferrite-ui/src/lib.rs` only — commit `aaec147`):** the
consent panel now renders both `FingerprintDiff` buckets. The old
rendering only ever iterated `extra_primitives`; `out_of_scope_origins`
was computed by A7's `compare()`, flagged, then silently dropped — never
shown, never gated, never enforced. `consent_items()` builds a
plain-English summary per flagged item from both buckets; out-of-scope
items are tracked in A7's unmodified `ConsentDecision` via a synthetic
`"origin::<origin>"` id. `consent_is_complete()` (checks both buckets)
replaces `ConsentDecision::is_complete()` as the Proceed/`ConsentSubmitted`
gate, re-checked inside the handler as defense-in-depth. Dry-run
evidence (`DryRunRecord`'s ordered call log + sanitizer-finding count)
is threaded through `ConsentRequired` and shown on an expand toggle.
`FilteredToolExecutor` also blocks a rejected origin for calls carrying
their own URL (`Navigate`/`DownloadFile`). Removed dead `approved_extras`
field (written, never read); fixed `pending_task` not cleared on
`ConsentCancelled`.

**Investigated, not just assumed:**
- Page-content decoupling: structural — `get_frame()` is the only path
  page content reaches this crate, as opaque RGBA pixels rendered via
  `iced_widget::image`, never parsed as markup. Pinned by
  `page_content_cannot_reach_the_consent_panels_inputs`.
- Reject-default-focus: iced 0.13's `button` doesn't implement
  `Focusable` (verified in `iced_widget`/`iced_core` 0.13 source — only
  `text_input`/`text_editor` do). Mitigated with reject-listed-first +
  strict completeness-gating; real fix needs an iced bump or a custom
  widget — filed **T-223**.

**Real limitation found, not fixed (`ferrite-ipi`, out of scope here):**
`FingerprintDiff::out_of_scope_origins`/`extra_primitives` never retain
the `(tool, origin)` pair together — the summary can say "origins your
task authorized somewhere" but not "primitive P needed origin O", and
`FilteredToolExecutor` can't origin-block a call with no URL of its own.
Filed **T-222**.
