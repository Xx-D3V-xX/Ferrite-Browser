Verified with a local page served under that kind of CSP: before the change `register()` rejected with `Cannot set value, expected trusted type`; after, `registered`. Not yet a regression test in the suite. **Known limit:** inside the worker, `importScripts('x.js')` with a plain string still meets the page's policy (the blob worker inherits it; a real service worker uses its own script's CSP). **Gmail, investigated, not fixed:** the spec lets a cross-origin window return a child frame by *name*; `windowproxy.rs` `GetSubframeWindowProxy` looks up only indexes, through the constellation's `GetChildBrowsingContextId`, which has no by-name form, and the constellation is not a vendored crate, so a fix needs a new message in an engine crate Ferrite does not carry. Whether `gtn-brain-iframe-id` even names a frame is unknown (if it does not, a real browser throws the same SecurityError). Remaining, unaddressed: `Blocked get of property "gtn-brain-iframe-id" on a cross-origin window` (from the T-322 check; the spec lets a cross-origin window return a child frame by name, which the traps do not do; whether that is the property's meaning is unknown) and `Error: int64` from Gmail's own script (cause unknown; the test page also checks `BigInt64Array`). |
